# ML Documentation — SAT-SA (SIH26157)

## 1. ML Objective

The machine learning component of SAT-SA (Supervisory Analytics Tool for SOC Assessment) is designed to evaluate and identify suspicious or performative SOC operational patterns across multiple organizations (entities). 

In supervisory SOC assessments, traditional rule-based checks can flag known violations, but they may miss novel, subtle, or complex behavioral anomalies where an entity's operational pattern diverges from peer standards. The unsupervised ML component creates a multi-dimensional behavioral profile per entity to detect overall operational anomalies. This allows supervisory authorities (such as NCIIPC/NTRO) to prioritize organizations for manual audit without needing pre-labeled training data or hardcoded heuristic thresholds for every edge case.

---

## 2. Feature Engineering

The Isolation Forest model evaluates entity behavior using a 6-dimensional feature vector aggregated from raw alert records. Each entity's alerts are summarized into the following features:

1. **`alert_count`**
   - **What it represents**: Total number of SOC alerts generated by the entity in the dataset.
   - **Utility**: Detects suspicious silence (an entity reporting unnaturally low alert volume relative to peers) or abnormal alert floods.

2. **`avg_closure_seconds`**
   - **What it represents**: Mean duration (in seconds) between alert creation timestamp (`created_time`) and closure timestamp (`closed_time`) across closed alerts.
   - **Utility**: Highlights performative closure behavior (e.g., closing complex alerts in under 5 minutes without genuine investigation).

3. **`escalation_rate`**
   - **What it represents**: The proportion of total entity alerts escalated to Tier-2 / Incident Response (`escalated == True`).
   - **Utility**: Identifies entities with near-zero escalation rates (indicating suppressed incidents or lack of thorough investigation) or abnormally high blanket escalations.

4. **`critical_ratio`**
   - **What it represents**: The fraction of total entity alerts categorized as `Critical` severity (`critical_alerts / total_alerts`).
   - **Utility**: Flags unusual severity distributions, such as complete absence of critical alerts when peer entities consistently report them.

5. **`avg_note_length`**
   - **What it represents**: Average character length of investigation notes across all alerts for the entity.
   - **Utility**: Identifies entities using empty, minimal, or copy-pasted template investigation notes ("Reviewed and closed", "No action required") compared to peers writing thorough documentation.

6. **`unique_asset_types`**
   - **What it represents**: Count of distinct asset categories (e.g., Server, Database, Endpoint, Network Device) generating alerts for the entity.
   - **Utility**: Exposes unmonitored infrastructure or blind spots where specific asset types produce no alerts.

## 3. Isolation Forest

### Model Selection & Architecture
- **Algorithm**: `sklearn.ensemble.IsolationForest`
- **Learning Type**: Unsupervised learning.
- **Entity Vectors**: Each entity $i$ is represented by a single 6-dimensional feature vector $X_i \in \mathbb{R}^6$.
- **Preprocessing**: Input features are normalized using `StandardScaler` to ensure features with large absolute ranges (e.g., `alert_count` in tens/hundreds, `avg_closure_seconds` in thousands) do not dominate bounded rate features like `escalation_rate` (0.0 to 1.0).

### Anomaly Scoring & Rescaling
1. **Tree Isolation**: Isolation Forest isolates anomalies by randomly selecting a feature and splitting values. Anomalous entities require fewer splits to isolate, resulting in shorter average path lengths in the trees.
2. **Raw Decision Function**: `clf.decision_function(X_scaled)` outputs raw decision scores where higher positive numbers indicate normal data points and negative numbers indicate anomalies.
3. **Inversion and Min-Max Rescaling**:
   $$\text{inverted} = -\text{raw\_scores}$$
   $$\text{score} = \frac{\text{inverted} - \min(\text{inverted})}{\max(\text{inverted}) - \min(\text{inverted})}$$
4. **Interpretation**: 
   - A score of `1.0` corresponds to the most anomalous entity in the dataset.
   - A score of `0.0` corresponds to the least anomalous entity.
   - **CRITICAL**: The final 0–1 score is a **relative min-max rescaling**, NOT a probability.

## 4. Final Configuration

The final parameters configured for the Isolation Forest detector are:

```python
random_state = 42
contamination = 0.2
n_estimators = 200
```

### Parameter Rationale
- **`random_state = 42`**: Fixes the random number generator seed to ensure 100% deterministic and reproducible results across demonstration runs and evaluation passes.
- **`contamination = 0.2`**: Specifies the expected proportion of outliers in the dataset used to set the internal decision threshold. This represents the assumed fraction of anomalous entities (e.g. 2 out of 10 entities). It is an operational parameter and must **NOT** be interpreted as a 20% probability of anomaly.
- **`n_estimators = 200`**: Expands the ensemble to 200 decision trees (from default 100), reducing variance in decision tree splits and producing a smoother, more stable decision boundary across small entity sample sizes.

To evaluate model stability across hyperparameter choices, five experimental configurations were tested:

| Experiment | `contamination` | `n_estimators` | Observations & Ranking Stability |

| **A** | `0.1` | `100` | Top entities identified reliably; lower-ranked entity ordering fluctuated slightly. |
| **B** | `0.2` | `100` | Good top-3 stability (Delta Rail, Indus Financial, Continental Banking). |
| **C** | `'auto'` | `100` | Threshold set automatically by scikit-learn; baseline separation was less distinct. |
| **D** | `0.2` | `50` | Faster execution but higher score variance between random seeds. |
| **E (Selected)** | `0.2` | `200` | **Highest ranking stability**: 200 trees smoothed out forest variance and preserved top entity ranking. |

### Validation Criterion
Ranking consistency was used as the primary validation criterion because:
1. The dataset contains a small cohort of 10 entities.
2. Isolation Forest is an unsupervised method operating without ground truth labels.
3. No train/test splitting or supervised metric (such as Accuracy, Precision, or Recall) is statistically valid or appropriate. **Model accuracy is not claimed.**

**Selection Rationale**: Configuration **E** (`n_estimators=200`, `contamination=0.2`) was selected as the optimal presentation configuration because 200 trees provided the most stable decision surface and rank ordering across random seed variations.

## 7. Rule-Based Detection

SAT-SA combines ML anomaly detection with two deterministic, rule-based detection modules:

### 1. Execution Gap Detector
Focuses on performative SOC indicators where work appears completed on paper but is procedurally hollow:
- **Fast Closure**: Critical/High severity alerts closed in under 300 seconds.
- **No Escalation**: Critical severity alerts closed without being escalated to Tier-2 / IR.
- **Template Notes**: Investigation notes that are empty, under 20 characters, or verbatim duplicated at rates significantly above peer baseline.

### 2. Negative Space Detector
Identifies security activity that ought to be present based on peer standards but is missing:
- **Low Alert Volume**: Entity alert volume significantly below peer baseline ($z \le -1.0$).
- **Missing Expected Severity**: Absence of alert severities (e.g. Critical or High) that are present across peer entities.

### Key Conceptual Distinction
> **Isolation Forest** identifies **unusual overall entity behavior** across high-dimensional feature space, whereas **deterministic rules** provide specific, audit-ready **supervisory signals** grounded in explicit domain logic.

## 8. Risk Score Integration

The outputs from all three detectors are integrated into a single unified entity Risk Score (0–100) by `risk_score.py`.

### Component Weights
- **Execution Gap**: 40% (`0.40`)
- **Negative Space**: 35% (`0.35`)
- **Anomaly (Isolation Forest)**: 25% (`0.25`)

### Soft Floor Attenuation
To prevent a single severe detector finding from being diluted when an entity scores zero on the other two detectors, a **continuous soft floor** (`FLOOR_ATTENUATION = 0.85`) is applied.

### Exact Mathematical Formula

$$\text{weighted\_sum} = 0.40 \times \text{execution\_gap} + 0.35 \times \text{negative\_space} + 0.25 \times \text{anomaly}$$

$$\text{floor} = \max(\text{execution\_gap}, \text{negative\_space}, \text{anomaly}) \times 0.85$$

$$\text{combined} = \max(\text{weighted\_sum}, \text{floor})$$

$$\text{risk\_score} = \text{round}(\max(0.0, \min(1.0, \text{combined})) \times 100, 1)$$

## 9. Explainability Framework

In accordance with SAT-SA's mandate for zero black-box outputs, every ML flag is paired with concrete, human-interpretable evidence:

1. **Component Scores**: Break down exact risk contribution across Execution Gap, Negative Space, and Anomaly scores.
2. **Primary Driver**: Automatically highlights which detector contributed most heavily to the entity's risk score.
3. **MAD-based Feature Attribution**: For the Anomaly score, features are evaluated against the peer median using Median Absolute Deviation (MAD) modified z-scores ($scale = 0.6745$):
   $$z_{\text{modified}} = 0.6745 \times \frac{x_i - \text{median}}{\text{MAD}}$$
   The top 2–3 most deviant features are rendered in plain language (e.g. *"Entity is 30.75 modified z-scores below the peer median for avg_closure_seconds"*).
4. **Evidence & Raw Traceability**: Execution Gap findings cite concrete `alert_id`s (e.g., `ALT00586`) with specific failure reasons, allowing auditors to verify flags against raw CSV records.

> **"No flag is presented without an explainable reason and supporting evidence."**

## 10. Limitations

1. **Synthetic Dataset**: Evaluation was conducted on a synthetic dataset of 639 alerts across 10 fake entities created for SIH testing.
2. **Small Cohort Size**: Peer baselines and median/MAD metrics are computed over 10 entities; addition or removal of entities alters peer distribution.
3. **Unsupervised Nature**: Isolation Forest ranks relative strangeness without supervisor-labeled ground truth; **no accuracy, precision, or recall claims are made**.
4. **Relative Rescaling**: Anomaly scores are relative to the current batch of entities uploaded into the system.
5. **Peer Dependence**: Negative Space and MAD feature attributions depend on the peer group present in the uploaded dataset.
