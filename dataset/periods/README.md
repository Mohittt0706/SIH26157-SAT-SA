# Multi-period dataset — answer key

Four quarterly CSVs, same 21 entities and same 8-column ingestion schema as
`dataset/soc_alerts_extended.csv` (`alert_id, entity_name, severity,
created_time, closed_time, escalated, investigation_notes, asset_type`).
Generated by `generate_periods.py` (fixed seed `20260915` — regenerating
reproduces byte-identical files; see that script for the exact per-quarter
knobs summarized below).

Uploading all four **in chronological order** through `POST /api/upload`
builds up four `AssessmentRun` audit records — the per-entity history the
trend feature plots against.

> **Regenerated 2026-09.** The previous version of this dataset was built
> against the retired 10-entity primary dataset (Delta Rail Systems / Indus
> Financial Services / Continental Banking Corp — none of which exist in the
> canonical roster any more). This version targets the 21-entity extended
> roster (`dataset/generate_extended.py` / `dataset/README_extended.md`),
> which is now canonical.

This file plays the same role for the trend feature that
`dataset/answer_key_extended_INTERNAL_ONLY.csv` plays for single-snapshot
detection: it says exactly which pattern was planted in which entity in
which quarter, so a reviewer can check the trend feature surfaces the right
direction for the right entity instead of just eyeballing a chart.

## Entity roster (21)

7 seeded entities with a deliberate trajectory (below), plus 14 baseline
entities with only small quarter-to-quarter noise around a fixed volume — no
baseline entity is constructed to outrank a seeded entity in any quarter:

Apex Power Grid Ltd, Bharat Telecom Networks, Cauvery Logistics Corp,
Eastern Grid Utility, Godavari Chemicals, Himalayan Healthcare Network,
Indus Financial Services, Jupiter Aviation Control, Krishna Port Authority,
Lakshmi Insurance Group, Malabar Gas Pipelines, Narmada Steel Works, Orissa
Mining Federation, Pennar Cement Industries.

## Planted patterns

### Saraswati Rail Network — deteriorating (negative space)

Near-normal in Q3, then alert volume collapses and the surviving severity
mix narrows every quarter — by Q2 it lands on the same collapsed profile as
`dataset/soc_alerts_extended.csv`'s single-snapshot Saraswati row (11
alerts, low/medium only). No execution-gap or anomaly overrides at any
point; volume + missing severities alone drive the signal.

| Quarter | Alert count | Severities present | Pattern |
|---|---|---|---|
| Q3 2025 | 180 | Low/Med/High/Critical | near-normal volume, full severity mix |
| Q4 2025 | 90 | Low/Med/High | volume roughly halved, critical disappears |
| Q1 2026 | 35 | Low/Med | pronounced drop, high disappears too |
| Q2 2026 | 11 | Low/Med | near-silence — matches the single-snapshot dataset exactly |

### Meridian Trust Bank — execution gap, worsening

Execution-gap present from Q3 and worsening every quarter, converging on
`dataset/soc_alerts_extended.csv`'s blatant single-snapshot Meridian profile
(~95% fast closure / ~90% no-escalation / 100% template notes) by Q2.

Alert count is deliberately held flat, near the 14-baseline band, in every
quarter — see "Why Meridian's blended score had to be re-tuned" below for
why a rising volume here would have worked against the intended trend.

| Quarter | Alert count | Fast closure | No escalation | Template notes | execution_gap score |
|---|---|---|---|---|---|
| Q3 2025 | 205 | 15% | 15% | 12% | 0.14 |
| Q4 2025 | 208 | 45% | 45% | 40% | 0.36 |
| Q1 2026 | 210 | 75% | 72% | 75% | 0.66 |
| Q2 2026 | 212 | 97% | 95% | 100% | 0.70-0.70 (near-ceiling) |

### Kaveri Power Holdings — execution gap, then remediated

Execution-gap present and peaking in Q3/Q4 (near the subtle single-snapshot
Kaveri profile), then clearly improving in Q1/Q2 as if remediation
happened. **This is the one seeded entity that gets better** — otherwise the
trend feature would only ever show one direction. Q2's rates are a
*partial* remediation, not a return to baseline — the entity should still
read as recently-improved, not as if the detector stopped looking.

| Quarter | Alert count | Fast closure | No escalation | Template notes |
|---|---|---|---|---|
| Q3 2025 | 230 | 52% | 62% | 36% |
| Q4 2025 | 240 | 58% | 68% | 39% |
| Q1 2026 | 245 | 40% | 45% | 30% |
| Q2 2026 | 250 | 42% | 45% | 33% |

### Why Meridian's and Kaveri's blended scores needed re-tuning

The first pass at this dataset set Meridian's rates lower and let its alert
count climb 250->285 across the four quarters. That produced a
monotonically-climbing `execution_gap` component as intended, but the
*blended* `risk_score` (40% execution_gap + 35% negative_space + 25% anomaly,
plus a soft floor at `max(any detector) * 0.85` — see
`backend/app/analytics/risk_score.py`) still fell from Q3 to later quarters,
because Q3's elevated alert count gave Meridian an outsized anomaly
component (0.891) at a moment when it had comparatively little competition
for "most anomalous entity" — a competition that stiffens in later quarters
as Konkan's and Saraswati's own patterns escalate. The soft floor picked up
that early anomaly spike and produced a start-high, decline-over-time shape
that read backwards on a chart even though the raw execution-gap rule rates
were climbing correctly underneath it.

The fix was generation-only, not a detector or weight change: Meridian's
alert count is now held flat near the baseline band in every quarter so its
own anomaly contribution stays modest and roughly proportional to its
rising fast-closure/no-escalation rates (which also pull
`avg_closure_seconds` down every quarter, reinforcing rather than fighting
the trend) instead of being dominated by a one-off volume spike early on.
Similarly, Kaveri's Q2 rates were raised from an earlier near-total
remediation (~8-12%, which put its blended score at 6.7 — below most
baselines) to ~35-45%, landing its Q2 blended score in the 25-35 range: a
real improvement over Q3/Q4's 85.0/51-55, but still visibly elevated rather
than indistinguishable from a clean baseline.

### Arcadia Defence Systems — anomaly volume spike, Q1/Q2 only

Near-baseline volume through Q4 (a hair above the 14 baselines' ~180-220/quarter
band, deliberately not enough to trigger anything on its own), then a sudden
step-change in Q1 that continues into Q2 — nothing gradual. Converges on the
760-alert single-snapshot Arcadia volume by Q2.

| Quarter | Alert count | Pattern |
|---|---|---|
| Q3 2025 | 225 | near-baseline |
| Q4 2025 | 235 | near-baseline |
| Q1 2026 | 620 | sudden spike |
| Q2 2026 | 760 | spike sustained — matches single-snapshot dataset |

### Konkan Maritime Ltd — multi-feature drift, building gradually

Alert *volume* stays flat at 190/quarter throughout (never trips
`LOW_ALERT_VOLUME` or an anomaly volume feature on its own) while four other
features drift together, gradually, across all four quarters: closure time
climbs, escalation rate climbs, the severity mix shifts toward
high/critical, and the number of asset types in play shrinks. No single rule
catches it in any one quarter — it's the feature vector as a whole that
drifts, converging on the single-snapshot Konkan profile (avg closure
~34,815s, escalation ~0.59-0.81, critical ratio ~0.20-0.22, 3 asset types)
by Q2.

| Quarter | Closure range | Escalation (Critical/High) | Critical+High share | Asset types in play |
|---|---|---|---|---|
| Q3 2025 | 170-270 min | baseline weighted rate (no override) | 28% | 8 (all) |
| Q4 2025 | 190-300 min | baseline weighted rate (no override) | 33% | 6 |
| Q1 2026 | 280-420 min | 72% / 60% (override) | 44% | 4 |
| Q2 2026 | 433-733 min (~26,000-44,000s) | 90% / 81% (override) | 52% | 3 (Server, Identity Provider, Cloud Workload) |

Q3 is deliberately mild — close enough to the peer baseline that it is not
yet the single most-anomalous entity that quarter. `anomaly.py`'s Isolation
Forest output is rescaled *relative to peers each quarter*, so an entity
that is already the most-anomalous peer in Q3 would saturate at the maximum
component score immediately and be unable to show gradual buildup. As
observed (see the results table below), Konkan's anomaly component still
reaches its ceiling from Q4 onward — the underlying feature drift keeps
building every quarter through Q2, but the *rescaled, peer-relative* score
plateaus once Konkan becomes the clear outlier, which happens a quarter
earlier than the raw feature drift alone would suggest.

severity alert exists in *any* quarter — flagged, but flat, not trending.
Matches the single-snapshot dataset's Nilgiri profile exactly in every
quarter.

| Quarter | Alert count | Severities present |
|---|---|---|
| Q3 2025 | 170 | Low/Medium only |
| Q4 2025 | 178 | Low/Medium only |
| Q1 2026 | 172 | Low/Medium only |
| Q2 2026 | 175 | Low/Medium only |

### Deccan Health Network — oscillating, volatile

Alternates between a mild quarter and a spike quarter, so it reads as
volatile rather than trending in either direction. Spike quarters land near
the single-snapshot dataset's "deliberately ambiguous" Deccan profile
(26.7% fast closure / 43% duplicated notes); mild quarters sit close to
baseline.

| Quarter | Alert count | Fast closure | No escalation | Template notes | Character |
|---|---|---|---|---|---|
| Q3 2025 | 200 | 4% | 6% | 4% | mild |
| Q4 2025 | 210 | 55% | 60% | 50% | spike |
| Q1 2026 | 200 | 5% | 8% | 5% | mild |
| Q2 2026 | 210 | 52% | 58% | 48% | spike |

(Widened from an earlier, gentler mild<->spike swing that stayed under the
trend classifier's volatility threshold and read as "stable" rather than
"volatile" — see the observed results below.)

### The 14 baselines — stable

Each baseline entity's alert count matches its `dataset/generate_extended.py`
single-snapshot value, with ±6% multiplicative noise applied independently
per quarter (`BASELINE_NOISE_FRACTION`). No execution-gap, negative-space,
or anomaly overrides at any point — every field falls back to the global
baseline distribution (`NORMAL_SEVERITY_WEIGHTS`, uniform asset types, the
150-210 minute closure range, `ESCALATION_RATE_BY_SEVERITY`).

**"No baseline outranks a seeded entity" means top-of-ranking, not every
single value.** As uploaded and scored (see the results table below), no
baseline entity is ever the highest- or even top-4-ranked entity in any
quarter — the top of the ranking is always occupied by whichever seeded
entities have an active pattern that quarter. A handful of individual
baseline *values* do land above a seeded entity's own score in a quarter
where that entity is deliberately quiet by design — Arcadia's near-baseline
Q3/Q4 before its volume spike, Deccan's mild oscillation troughs, and
Kaveri's Q2 after remediation — which is the intended behavior, not noise: a
detector should not flag Arcadia in Q3, and should not still flag Kaveri
after it has genuinely improved. This mirrors the known caveat already
documented in `dataset/README_extended.md` (baseline NO_ESCALATION rates
ranging ~0.08-0.56 off small critical-severity samples) — the same
small-sample noise applies per quarter here and is what produces baseline
scores in the ~10-42 range rather than a flat near-zero.

(execution_gap, negative_space, anomaly). Baseline entities have no

**6 of 7 seeded entities match their designed direction label exactly.**
Meridian Trust Bank and Kaveri Power Holdings were the two entities fixed
in this pass (see "Why Meridian's and Kaveri's blended scores needed
re-tuning" above); Deccan Health Network's oscillation amplitude was widened
in the same pass to clear the volatility threshold. Konkan, Saraswati, and
Arcadia already matched on the first pass and needed no changes here.

**Nilgiri Water Authority remains a genuine, reported disagreement — not
fixed.** Its per-quarter profile is *literally identical* every quarter (175
+/- a few alerts, low/medium-only severity, no other override — see its
planted-pattern table above), by design, to test a flat-but-flagged signal
distinct from a deteriorating one. But the app's classifier reads its
blended score as "improving" (62.9 -> 38.0 -> 29.1 -> 27.4) because
`negative_space.py` and `anomaly.py` are both peer-relative: Nilgiri's own
MISSING_EXPECTED_SEVERITY signal and its Isolation Forest ranking are scored
against *that quarter's* peer set, and every other seeded entity in this
dataset is designed to become more extreme over the same four quarters
(Meridian, Konkan, Saraswati all escalate; only Kaveri eases, and only
partially). As those peers pull further from baseline, an unchanged Nilgiri
becomes comparatively less unusual each quarter, purely by not moving while
everything around it does. This is not fixable by further tuning Nilgiri's
own generation knobs without contradicting the entity's actual design
intent (a profile that repeats exactly) — doing so would turn it into a
second deteriorating-or-improving entity instead of the flat-signal control
case it is meant to be. It is reported here rather than patched.

## Regenerating

`python generate_periods.py` from this directory — deterministic, produces
byte-identical output. Entity roster, baseline value pools, and each seeded
entity's converged (final-quarter) values are kept in sync with
`dataset/generate_extended.py` by hand; if that script's roster or profiles
change, update `ENTITY_NAMES` / `BASELINE_ALERT_COUNT` / `SEEDED_PROFILES`
here to match.
